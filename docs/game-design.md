## 2. 核心循环（最重要）

玩家反复做的那件事，以及为什么好玩。写成「动作 → 反馈 → 变化」的三段式。

1.玩家点击F键
2.章鱼抬起触手击打，并随着惯性稍微移动
3.章鱼移动，被击打的小型物体破碎，大型物体变形，生物受到伤害

**失败条件：**被追击的武装人员击败
**胜利 / 结束条件：**逃离试验基地（大胜）/进入实验室下一区域（小关卡结束）
**一局时长：**2min（建议 ≤ 2 分钟，方便演示和评委试玩）

## 8. 技术决策记录（评审后确认）

> 这一节由环境搭建阶段补写，记录**已经影响代码实现**的决定，避免后面反复。

### 8.1 取消跳跃，改为「触手扑击 / 喷射位移」（2026-10-14 确认）

原文档写了「空格跳跃」，但**等轴测俯视角没有天然的垂直轴**，实现跳跃必须做伪高度
（精灵 Y 偏移 + 影子缩放 + 碰撞体分层 + 与瓦片的遮挡排序），估计 1–2 小时且容易出排序 bug。

**决定**：不做跳跃。垂直方向的动感由扑击提供 —— 按 F 时给自身一个前冲速度，
带惯性滑行，同时判定身前圆形范围。已按此实现（`PlayerController.cs`）。

**影响**：`空格` 键空出来了，可以留给「喷射冲刺」或「下潜」，看后续手感需要。

### 8.2 其余待定项（还没写死，开工前最好定）

- **W/S 描述笔误**：文档 4.1 里 W/S 写的是「向前移动 / 向右移动」，应为「向上 / 向下」。
  等轴测下 WASD 会映射到屏幕方向（W = 屏幕上、D = 屏幕右）。
- **「明确不做的事」还是空的**：建议至少写上「不做存档」「不做程序化地图生成」
  「敌人只做直线追击、不接寻路」「不做多结局」。
- **roguelike 的局内成长环缺失**：目前核心循环是「击打 → 破坏」，缺少 roguelike 的
  成长/随机要素。要么补一条（如破坏可获得突变/触手升级、房间随机组合），
  要么把作品定位改成「潜行破坏动作游戏」，否则评委会按 roguelike 的期待验收。
- **Dither 风格实现路径**：建议走 **Built-in 全屏后处理**（`OnRenderImage` + Bayer 矩阵），
  一次覆盖全场，比逐个 sprite 写 shader 省事得多。

### 8.3 硬件与环境约束（影响技术选择）

- 本机 15.5GB 内存 / 16 逻辑核：2D 项目够用，**不要开大型 3D 场景或烘焙光照**。
- Unity 中国源（`packages.unity.cn`）当前网络不稳，首次包解析曾耗时 40 分钟。
  **一旦解析完成，不要随意改动 `Packages/manifest.json`**，否则会重新解析。
- 已装 `com.unity.2d.tilemap.extras`（等轴测瓦片）与 `com.unity.2d.pixel-perfect`，
  像素风所需的东西齐了。
